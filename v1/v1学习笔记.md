# 电梯网站项目学习笔记

## 阶段一：分级概览 (V1)

- **学习时间**：2026-03-04
- **架构模式**：采用语义化 HTML 结构（`<header>`, `<main>`, `<article>`），增强了 SEO 和无障碍访问。
- **样式方案**：
    - **Tailwind CSS**：处理响应式网格布局 (`grid-cols-1 md:grid-cols-2 xl:grid-cols-3`) 和原子类间距。
    - **自定义 CSS (`styles.css`)**：实现了 `.hero-bg` 的三重混合渐变和 `.card` 的平滑升降动效 (`translateY`)。
- **数据结构**：数据硬编码在 HTML 中，作为 UI 演示版本，非常适合学习 CSS 布局和基础组件化思维。

---

## 阶段二：技术体系与查阅逻辑

### 1. 技术栈框架构成

- **HTML5 (语义化结构)**: 负责内容的层级划分。
- **Tailwind CSS (原子化样式工具)**: 负责大部分的排版、间距和响应式设计。
- **Custom CSS (定制化视觉)**: 处理 Tailwind 难以实现的复杂视觉效果。

### 2. 代码查阅建议顺序

1. **入口分析**: 查看 `index.html` 的 `<head>`，确认依赖关系。
2. **宏观分区**: 快速浏览 `<body>` 下的一级标签。
3. **样式基调**: 研读 `styles.css`，理解视觉“大招”。
4. **微观拆解**: 聚焦 `index.html` 中的重复组件（如 `article.card`）。

## 阶段三：拆解互动

### 知识点：HTML (网页的身份证与工具箱)

- **解析要点**: 字符集 (UTF-8) 必须置于最前；`<title>` 物理上位于 head 但逻辑上影响全局；Viewport 决定响应式生死。
- **高级功能**: 外部字体、资源预热 (Preload)、PWA 配置。
- **显示逻辑**: `<head>` 属于“后台”，在网页画布上默认完全不可见。

### 知识点：响应式开发调试 (全场景方案)

- **方案**: Wi-Fi 局域网、手机热点模式、USB 端口转发 (Chrome Inspect)。
- **意义**: 解决跨设备视觉差异，实现“真机实时预览”。

### 知识点：CSS 多重背景渐变 (Hero 背景魔法)

- **核心**: 多个 `radial-gradient` 叠加在一个底层的 `linear-gradient` 之上。
- **视觉**: 模拟环境光晕，增强页面层级感。

## 阶段四：开发环境调优 (避坑指南)

### 知识点：Live Server 频繁刷新/夺取焦点

- **对策**: 设置 `ignoreFiles` 屏蔽 `.md` 文件；将 Auto Save 改为 `onWindowChange`；增加刷新延迟。

### 知识点：HTML 常用标签家族

- **布局**: `<header>`, `<main>`, `<nav>`, `<footer>`。
- **组件**: `<section>`, `<article>`, `<aside>`, `<div>`, `<span>`。

---

## 阶段五：Main 区域与 Article 卡片深度解析

### 1. HTML 语义深度

- **`<article>`**: 标记独立、完整的信息单元（单个电梯卡片）。
- **`<ul>/<li>`**: 结构化展示参数，取代无意义的 div 堆砌。

### 2. Tailwind 布局技巧

- **Grid 智能网格**: `grid-cols-1 md:grid-cols-2 xl:grid-cols-3` 适配手机到电脑。
- **Flex 自动对齐**: `justify-between` 实现左右两极对齐，`items-center` 确保垂直居中。

### 3. Custom CSS 视觉魔法

- **磁悬浮动效**: `.card:hover` 的 `translateY(-4px)` 增加物理反馈感。
- **性能优化**: `.card-image` 利用 CSS 斜纹理替代真实图片。

3. **布局的“收缩力”**:
    - 深刻理解了 `max-w` 减小后的视觉聚焦效应，实现了“视野收拢，但不压迫”的心理暗示。

## 阶段八：全案总结与复盘 (Post-Mortem)

### 1. 核心收获：从“还原”到“对标”

在本阶段，我们不仅复原了代码，更完成了一次*_“基于业务语义的二次创作”*_。通过对《电梯网站.md》的深度研读，我们将原本通用的科技风格，重塑为更符合电梯物理属性的“工业金属风”。

- **经验**: 设计不是凭空想象，而是对业务属性（电梯的垂直、密闭、金属感）的精准翻译。

### 2. 技术栈协同效率

- **HTML**: 提供了坚固的语义化地基（`<article>`, `<ul>`），确保了信息的逻辑性。
- **Tailwind**: 极大缩短了“重排布局”的时间。通过修改 `max-w-4xl` 和 `grid-cols-2`，我们只用几秒钟就完成了“视野收拢”的宏观调整。
- **Custom CSS**: 弥补了原子化框架在“氛围感”上的不足。`Vignette` 和 `Metallic Texture` 让页面具备了超出一般网页的质感。

### 3. 开发环境与工作流

通过调优 Live Server 的忽略规则，我们实现了 **Obsidian 记录** 与 **VS Code 开发** 的完美同步。这套“一边编码、一边总结、最后分发知识点”的工作流，是高效学习全栈技术的最佳实践。

**V1 结论**：结构已稳，视觉已美。V1 作为一个纯静态演示版，已经超额完成了“奠定基调”的任务。

## 阶段九：问答细节与具象比喻复盘 (Retrospective)

### 1. 那些被内化的比喻

本次学习中，最有效的不是记住了类名，而是理解了类名背后的**物理模型**：

- **“后台与舞台” (Head vs Body)**: 理解了资源加载与视觉呈现的物理隔绝。
- **“拔河比赛” (Flex justify-between)**: 具象化了子元素争夺剩余空间的动力学过程。
- **“磁悬浮” (translateY & shadow)**: 将代码交互映射到了真实的物理重力感。
- **“阅读聚光灯” (max-w & text-color)**: 掌握了如何利用视觉层次保护用户的眼球（阅读舒适度）。

### 2. 问答中的逻辑闭环

通过不断的“为什么”询问，我们拆解了 `slate-200` 为什么比纯白更适合做次级信息，以及为什么 `tracking-widest` 能产生工业美感。这些**“碎片化的为什么”**最终拼凑成了完整的**“高级感设计语言”**。

### 3. 下一阶段展望

V1 解决了*_“静态美学”*_。 V2 将解决*_“动态逻辑”*_：如何用 JS 优雅地操纵这些带有“工业美感”的卡片，实现筛选与交互。
