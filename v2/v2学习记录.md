# 电梯百科 V2 学习记录

> **学习目标**：理解从“静态页面”到“数据驱动页面”的跨越，掌握基础的 JavaScript 状态管理与 DOM 渲染。

## 核心差异概述 (V1 vs V2)

| 特性 | V1 (静态版) | V2 (交互版) |
| :--- | :--- | :--- |
| **数据来源** | 直接写死在 HTML 中（Hardcoded） | 异步加载 `data/elevators.json` |
| **交互能力** | 仅有 CSS 悬停效果 | 实时筛选、清空重置、详情弹窗 |
| **渲染方式** | 浏览器直接解析 HTML | JS 根据数据动态生成 HTML 节点 |
| **复杂程度** | 纯展示，无逻辑 | 引入了“状态 (State)”的概念 |
| **可维护性** | 修改数据需要改动 HTML 结构 | 只需更新 JSON 文件，代码自动适配 |
**所以js其实只要把里面的数据是如何流动看懂就能看懂整个代码的逻辑,按照这个思路，所有的代码都可以这样做**

## 架构实现优先级建议 (How to Build)

如果你要从零实现类似 V2 的功能，为了保证**稳定性**和**可扩展性**，建议遵循以下优先级：

1.  **【第一优先级】定义数据契约与状态 (Data & State First)**
    *   **动作**：建立 `state` 对象（应用的大脑）与 `elements` 对象（神经末梢）。
    *   **核心逻辑**：
        *   `state`：集中管理 `elevators`（原始库）、`filtered`（展示架）、`selected`（焦点项）。
        *   `elements`：通过 `document.getElementById` 缓存 DOM 引用，避免重复查询。
    *   **关键概念**：
        *   **DOM (Document Object Model)**：HTML 的“树状地图”，JS 操作网页的接口。
        *   **ID 钩子**：JS 寻找 HTML 的精准坐标，找不到会返回 `null`。
        *   **A11y (无障碍)**：`aria-hidden` 等属性确保对辅助设备友好。

2.  **【第二优先级】打通数据管道 (Data Pipeline)**
    *   **动作**：实现 `async function loadData()`。
    *   **核心逻辑**：
        *   `fetch`：发起网络请求（点外卖）。
        *   `await`：非阻塞等待（等快递），让异步代码像同步一样好读。
        *   `try...catch`：防御性编程，捕获网络异常或数据格式错误。
        *   `[...]` (展开运算符)：浅拷贝数据，确保原始数据与展示数据互不干扰。
    *   **流程**：请求 -> 状态码校验 (`response.ok`) -> 解析 JSON -> 数据校验 -> 同步到 `state` -> 触发渲染。
3.  **【第三优先级】核心过滤引擎 (Filtering Engine)**
    *   **动作**：实现 `applyFilters` 逻辑，处理“全部”逻辑和多条件交叉过滤。
    *   **理由**：这是纯逻辑层，不涉及 DOM。先把它写稳，后续无论增加多少个筛选框（如搜索框、排序），只需往这个函数里加逻辑即可，扩展性极强。
4.  **【第四优先级】动态渲染模板 (Template Rendering)**
    *   **动作**：实现 `renderCards`，将单个对象转化为 HTML。
    *   **理由**：将渲染逻辑封装成函数。后续数据变了，只需重新调用该函数，UI 自动同步，保证了视图的一致性。
5.  **【第五优先级】UI 事件绑定与反馈 (Interactive & Feedback)**
    *   **动作**：绑定 `change` 事件、`reset` 按钮、状态文字提示。
    *   **理由**：在稳定的逻辑引擎上覆盖交互层。
6.  **【第六优先级】非核心增强功能 (Secondary Features)**
    *   **动作**：弹窗详情、键盘辅助、错误处理提示。
    *   **理由**：这些属于“锦上添花”，不影响核心链路。

## JS 代码查阅建议顺序 (Data Flow)

1.  **【定义状态】`const state`** (第 1-5 行)
    *   **为什么先看**：这是整个应用的“大脑”。先搞清楚程序记住了哪些信息（原始数据、筛选后的数据、当前选中的电梯）。
2.  **【加载数据】`async function loadData()`** (第 167-187 行)
    *   **为什么看**：了解数据是怎么从外部文件“飞”进程序里的。你会学到 `fetch` 和 `async/await` 的基本用法。
3.  **【初始化筛选】`function initFilters()`** (第 111-127 行)
    *   **为什么看**：看程序如何根据数据自动生成下拉框选项（去重逻辑），以及如何监听用户的点击。
4.  **【执行筛选】`function applyFilters()`** (第 93-101 行)
    *   **为什么看**：这是逻辑核心。理解如何根据用户选中的条件，从 100% 的数据中过滤出符合条件的 20%。
5.  **【渲染界面】`function renderCards()`** (第 35-77 行)
    *   **为什么看**：看 JS 是如何把枯燥的数据对象转化为带有样式的 HTML 卡片的。
6.  **【弹窗逻辑】`openModal / closeModal`** (第 129-165 行)
    *   **为什么看**：了解 UI 交互中常见的“详情展示”和“键盘辅助（如 Esc 关闭）”是如何实现的。

### V2 版本架构终极复盘：从“静态”到“引擎”的跨越

| 维度 | V1 (原始版本) | V2 (数据驱动版本) |
| :--- | :--- | :--- |
| **核心驱动** | HTML 标签驱动 (写死在页面) | **Data 驱动** (JSON -> State) |
| **扩展性** | 增加电梯需手动改 HTML 源码 | 增加电梯只需更新 elevators.json |
| **逻辑复杂度** | 只有简单的 CSS 显隐切换 | 拥有多维度的 **逻辑过滤引擎** |
| **代码组织** | 逻辑与结构混在一起 | **职责分离** (State / Logic / Render) |
| **交互体验** | 基础点击，无反馈，无动画 | 磨砂玻璃质感、锁屏弹窗、全键盘支持 |
